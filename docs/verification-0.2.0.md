# DSH 0.2.0 接入改造验收

日期：2026-10-08。目标宿主：官方 npm 发布的 `@deepseek-ai/dsh@0.2.0-rc.2`，Cordis `4.0.4`，Schemastery `3.18.4`，pi-ai `0.87.1`。

本轮完成本地实现与打包，未推送、发布插件，也未替换本机原有 DSH 或用户 profile。插件版本号仍为 `0.1.3`；本轮安装包是工作区构建产物，不代表远程同版本已包含这些改动。

## 实现范围

- 原生“设置 → CodeBuddy”，包含“账号与连接”和“模型与运行”。使用宿主 Button/Input 和中英文 locale 字典。
- 默认站点使用 volatile Config 与 `settings.update(entry.options.id, patch)` 持久化，保存后读回确认；命令省略站点时读取相同偏好。
- 设置页、命令、模型适配器共用账号与刷新协调服务；OAuth 与 `CODEBUDDY_OAUTH` 的存储格式保持原样。
- 保留可查询的登录成功、失败、取消状态，模型错误独立于账号状态，目录失败保留缓存。
- 默认模型与推理等级仅写宿主 `agentDefaultModel`；拒绝未登录、缓存目录、目录外模型、不适用的推理等级，以及未实际保存的写入。
- 管理接口使用 DSH 受认证 `/api` 载体，输入字段白名单与错误脱敏，不向客户端返回访问/刷新令牌。
- 补齐 0.2.0 的 system/tool 消息合同；账号变更会使准备中的调用和流式请求失效。

## 已执行验证

| 验证 | 结果与边界 |
| --- | --- |
| `npm run check` | 类型检查、55 项测试、服务端与浏览器入口构建通过 |
| 实际 DSH 安装 | `npm pack` 产物通过目标版本 `dsh plugin add` 装入隔离 profile；分别启动 Web 和仅基础服务的命令 profile |
| Web 原生页面 | Windows Edge 无界面浏览器中打开宿主设置，选择自定义站点、保存、点击登录、读取授权链接、选择模型/推理档位并保存；中英文页面均正常渲染，页面脚本无错误 |
| 认证与来源限制 | 无 cookie 管理请求返回 401；带有效 cookie 但来源不受信任返回 403 |
| OAuth | 本地模拟 `auth/state → auth/token → login/account`；验证成功、取消、退出；未使用真实账号 |
| 模型目录 | 模拟成功和 HTTP 503；失败保留账号与目录缓存，恢复后可再次刷新 |
| 持久化 | 完全停止并重新启动宿主，默认站点、默认模型、推理档位、已保存凭据均可读回 |
| 命令环境 | 无 Connection/Web 服务时，通过真实 Commands/Agents/Llm 服务运行登录、状态、退出；模拟服务收到流式 completion 请求并返回正文、usage 和终态 |
| 竞态回归 | 排队凭据写入取消、写入中取消回滚、退出后的旧刷新、授权链接生成时取消、复用登录调用者取消、宿主列模型与管理刷新去重、旧请求结果丢弃 |
| 配置失败 | 单元测试覆盖只读、无效 URL、宿主 no-op 保存；未修改 Windows 文件 ACL 做只读文件系统测试 |

所有 CodeBuddy 网络响应均来自本地模拟服务；“真实宿主”与“真实账号”是两种不同验证，本轮只完成前者。Web 截图与脱敏宿主日志位于工作区 `.tmp/verification-artifacts/`。

复现命令和依赖准备见 [README](../README.md#隔离宿主验收)。测试脚本只写工作区 `.tmp/verification-home`、`.tmp/verification-commands-home`，两个模式不共享凭据。

## 两路代码复查

**Standards**：明确规范违反 0；发现推理档位重复定义 1 条建议，已改为共享 `REASONING_LEVELS`。

**Spec**：发现 4 项（凭据取消、刷新竞态、生成授权 URL 时无法及时取消、宿主控件与本地化不完整），均已修复。复查发现的复用登录调用者取消边界也已修复，并有回归测试。无尚未处理的代码发现。
